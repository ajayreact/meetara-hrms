Idempotency that is visible in source: the `200000` through `250000` files and the lifecycle file check `hasTable` or `hasColumn` before creating objects. The invitation file throws if the lifecycle table or `subject_email` is missing, so a retry after a failed precondition does not create the invitation table. The repair file returns when the column already matches and throws when it does not. MySQL DDL commits each statement, so a failure after one `ALTER` can leave a column without a migration row. The repair file says that in its exception text.

`2026_10_19_250000` `down()` does not undo `tickets.description`, `overtime_entries.reason`, or `notifications`. That is a partial rollback even on a disposable database.
